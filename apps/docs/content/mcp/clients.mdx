# Connecting a client

Every client uses the same URL, `https://www.envpilot.dev/api/mcp`, and **no `Authorization` header**. The client finds the sign-in on its own and opens your browser. For what happens next, see [MCP setup](/mcp/setup).

Using an API key today? Follow [Moving from an API key](/mcp/setup#moving-from-an-api-key) first.

### Claude (web, Desktop, mobile, Cowork)

1. Open **Customize → Connectors** and choose **Add custom connector**. On Team and Enterprise plans an Owner adds it under **Organization settings → Connectors**.
2. Enter `https://www.envpilot.dev/api/mcp` as the server URL. Leave the OAuth client fields empty.
3. Select **Connect** and sign in to Envpilot in the window that opens.

Do not paste an Envpilot API key into an **OAuth Client Secret** field. That field authenticates an OAuth client during a token exchange; it never becomes the `Authorization` header on MCP requests.

### Claude Code

```bash
claude mcp add --transport http --scope user \
  envpilot https://www.envpilot.dev/api/mcp
```

Run `/mcp` in a session, choose `envpilot`, then **Authenticate**. A browser window opens for the Envpilot sign-in.

Choose the configuration scope deliberately:

- `--scope local` (the default) keeps the server private to you in the current project.
- `--scope project` writes `.mcp.json` for the team. It holds only the URL, so it is safe to commit; each person signs in for themselves.
- `--scope user` makes it available to you across projects.

`claude mcp list` only confirms the server is saved. `/mcp` shows whether it is signed in and its tools loaded. `claude mcp add` does not overwrite an existing entry, so remove a key-based `envpilot` entry first with `claude mcp remove envpilot`.

### Codex CLI, desktop, and IDE extension

```bash
codex mcp add envpilot --url https://www.envpilot.dev/api/mcp
codex mcp login envpilot
```

Or add it to `~/.codex/config.toml` and run `codex mcp login envpilot`:

```toml
[mcp_servers.envpilot]
url = "https://www.envpilot.dev/api/mcp"
```

Leave out `bearer_token_env_var`; that is the old key setup. If your Codex version has no `codex mcp login`, update Codex. Run `/mcp` to confirm the Envpilot tools are present.

### Cursor

Add the server to `~/.cursor/mcp.json`, or `.cursor/mcp.json` for a project:

```json
{
  "mcpServers": {
    "envpilot": {
      "url": "https://www.envpilot.dev/api/mcp"
    }
  }
}
```

Open Cursor's MCP settings. The server shows that it needs a login; select it and sign in.

### VS Code

Add the server to `.vscode/mcp.json` in a workspace, or to your user MCP configuration:

```json
{
  "servers": {
    "envpilot": {
      "type": "http",
      "url": "https://www.envpilot.dev/api/mcp"
    }
  }
}
```

Start the server from the MCP view and follow the sign-in prompt.

### One-click installs

The connector is also listed where clients look for servers, so you can skip
the command.

**Claude Code plugin.** Installs the server and a `bootstrap-env` skill that
gets a fresh checkout running without reading secret values into the
transcript:

```bash
/plugin install envpilot --marketplace rafay99-epic/envpilot.dev
```

The plugin registers the server as `plugin:envpilot:envpilot`, so its tools
appear as `mcp__plugin_envpilot_envpilot__*` in permission rules.

**Cursor.** Use the "Add to Cursor" button in the
[repository README](https://github.com/rafay99-epic/envpilot.dev), or the
deeplink:

```
cursor://anysphere.cursor-deeplink/mcp/install?name=envpilot&config=eyJ1cmwiOiJodHRwczovL3d3dy5lbnZwaWxvdC5kZXYvYXBpL21jcCJ9
```

**MCP registry.** The server is published as `dev.envpilot/mcp`, which is what
feeds the VS Code MCP gallery and the third-party directories. Search for
`envpilot` rather than pasting a URL.

### Dev containers and Codespaces

A container has the same problem a new clone does: the code is there and
`.env` is not. Install the CLI as a Feature so the container can fetch its own
environment:

```jsonc
// .devcontainer/devcontainer.json
{
  "features": {
    "ghcr.io/devcontainers/features/node:1": {},
    "ghcr.io/rafay99-epic/devcontainer-features/envpilot:1": {},
  },
}
```

The `node` Feature is required: the CLI is an npm package, and the Envpilot
Feature fails with a clear message rather than half-installing if npm is
absent. Pin a CLI version with `{ "version": "1.23.1" }` if you need one.

Sign-in still needs a browser once per container, so `envpilot login` is a
human step. For an unattended container, use an API key and the
[REST API](/api/quickstart) instead.

### Other clients

Any client that supports MCP authorization works: give it the URL and no header. It discovers the sign-in from the server's `401` response. A client that only supports static headers cannot connect; use the [REST API](/api/quickstart) or `envpilot run` for those jobs.

### More than one organization

If your account belongs to several organizations, pass `organization` (the organization's slug) to the project tools; `envpilot_get_doc` and `envpilot_update_doc_draft` take a doc id instead. The error message lists the slugs you can use.
